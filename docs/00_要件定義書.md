# TripDiary 要件定義書

Nov 14, 2026 · @masatsumaple-creator

## 1. 目的
旅行で訪れたスポットを、写真・感想・住所つきで記録し、地図上で見返しながら他のユーザーと共有できる旅行記録アプリです。講座課題として、実際に AWS へデプロイして動作させるところまで作ります。

| 観点 | 内容 |
|---|---|
| 記録 | 訪れたスポットを場所名・感想・写真・住所で残せる(住所は現在地から自動入力も可) |
| 共有 | 投稿を公開範囲を選んで共有し、いいね・コメント・フォローで反応できる |
| 探索 | エリアタグで絞り込み、地図上でスポットを確認し、「訪問済み/行きたい」でリスト管理できる |

## 2. 想定ユーザー・利用シーン

| ユーザー | 利用シーン |
|---|---|
| 旅行好きの個人 | 旅行中・旅行後にスポットを記録し、地図と一緒に思い出として見返す |
| 友人・フォロワー | 他の人のおすすめスポットを探し、行きたい場所に追加する |
| 閲覧のみの訪問者 | ログインせず公開投稿を閲覧する |

## 3. スコープ

| 作る | 作らない(初期版) |
|---|---|
| ユーザー登録・ログイン | SNS 連携ログイン |
| スポット投稿(場所名・感想・写真・住所) | 動画の投稿 |
| 現在地からの住所自動入力(補助機能) | 現在地周辺のスポット検索 |
| 地図表示(スポットのピン表示) | 経路検索・ナビ |
| いいね、コメント、フォロー | ダイレクトメッセージ、通知(メール/プッシュ) |
| エリアタグ絞り込み(都道府県) | 旅行費用管理、旅程(行程表)作成 |
| 訪問済み/行きたいリスト | |

## 4. 機能要件

| 機能群 | 内容 |
|---|---|
| 認証 | 新規登録、ログイン、ログアウト。JWT(アクセストークン)+ リフレッシュトークン。パスワードは保存時にハッシュ化 |
| スポット投稿 | 場所名(必須)、感想、写真(最大 20 枚)、住所(自由記述)、緯度・経度、エリアタグ(1〜3 個)、公開範囲の登録・編集・削除 |
| 現在地から住所入力 | ブラウザの位置情報で現在地を取得し、住所と緯度・経度を自動入力する。許可拒否・取得失敗時や旅行後の投稿では手入力・地図上での位置指定に切り替えられる |
| 地図表示 | スポットの位置をピンで表示。ピンから詳細へ遷移。閲覧可能な投稿のみ表示 |
| いいね | 投稿へのいいね/取り消し、件数表示 |
| コメント | 質問やおすすめ追加のコメント投稿、自分のコメントの削除 |
| フォロー | ユーザーのフォロー/解除、フォロー中ユーザーの投稿一覧 |
| 探索・絞り込み | エリアタグ(47 都道府県の固定一覧)での絞り込み、新着一覧 |
| 近くのスポット | スポット詳細に、同じエリアタグの他の投稿をおすすめとして表示する(下記) |

### 近くのスポット(おすすめ表示)
- 表示場所はスポット詳細。見ている投稿と同じエリアタグ(都道府県)を持つ他の投稿を、最大 5 件表示する
- 対象は閲覧可能な投稿のみ(公開範囲は API 側で判定する)。表示中の投稿自身は除く
- 並び順は初版では新着順とする(いいね順や距離順は将来の改善)
- 距離計算は行わない。「現在地周辺のスポット検索」(作らない)とは別で、現在地は使わない
| スポットリスト | 自分の投稿は自動で「訪問済み」。他人の投稿は「行きたい」から始め、訪問後に「訪問済み」へ変更できる |
| プロフィール | ユーザーの投稿一覧、フォロー数・フォロワー数 |

### 公開範囲

| 値 | 閲覧できる人 |
|---|---|
| 公開(public) | 未ログインを含む全員 |
| フォロワー限定(followers) | 投稿者本人と、投稿者をフォローしているログイン済みユーザー |
| 非公開(private) | 投稿者本人のみ |

### 権限マトリクス

| 操作 | 未ログイン | 本人 | 第三者(ログイン済み) |
|---|---|---|---|
| 公開投稿の閲覧 | ○ | ○ | ○ |
| フォロワー限定投稿の閲覧 | × | ○ | フォロワーのみ ○ |
| 非公開投稿の閲覧 | × | ○ | × |
| 投稿の作成 | × | ○ | - |
| 投稿の編集・削除 | × | ○ | × |
| いいね・コメント・フォロー | × | (自分への操作は不可) | ○(閲覧できる投稿に限る) |
| コメントの削除 | × | 自分のコメント、自分の投稿上のコメント | 自分のコメントのみ |
| リスト管理 | × | ○(自分のリストのみ) | - |

## 5. 非機能要件

| 観点 | 要件 |
|---|---|
| セキュリティ | アクセストークンは短寿命(例: 15 分、仮)。リフレッシュトークンは HttpOnly Cookie で保持し、DB にはハッシュのみ保存しローテーションする。SQL はプレースホルダで実行。秘密情報はコードに含めず環境変数/Secrets Manager で管理 |
| 権限 | API 側で本人・公開範囲を必ず検証する(画面制御だけに頼らない) |
| 入力検証 | サーバー側で必須・文字数・形式を検証。エラー応答の形式は統一。住所は最大 255 文字 |
| 画像 | 形式は JPEG/PNG/WebP、1 枚あたり 5MB 以下、1 投稿あたり 20 枚まで。ブラウザ側で縮小してから、署名付き URL で S3 へ直接アップロードする |
| 性能 | 一覧は 20 件程度ずつのページング。地図は表示範囲内のスポットのみ最大 100 件取得。厳密な SLA は設けない |
| 位置情報 | 現在地は投稿者が許可した場合のみ取得し、ブラウザには保存しない。緯度・経度は公開範囲に従って API から返す(閲覧権限のない人には返さない) |
| API 仕様書 | OpenAPI(Swagger)を自動生成して公開 |
| UX | スマートフォン幅でも利用可能なレスポンシブ対応。位置情報は HTTPS 必須 |
| プライバシー | 非公開・フォロワー限定の投稿は権限のない人に API でも返さない。画像 URL の推測を困難にする |
| コスト | 大量課金を避ける。NAT Gateway 等の高額リソースは使わず、終了後は `terraform destroy`。地図・逆ジオコーディングは無料枠内で使う |

## 6. 画面構成

| ID | 画面 | 概要 |
|---|---|---|
| S-01 | ログイン/新規登録 | 認証 |
| S-02 | ホーム(新着一覧) | 閲覧可能な投稿、エリアタグ絞り込み |
| S-03 | フォロー中一覧 | フォローしたユーザーの投稿 |
| S-04 | スポット詳細 | 写真、感想、住所、小地図、いいね、コメント、リスト追加 |
| S-05 | スポット投稿/編集 | 入力フォーム、写真アップロード、現在地から入力、地図で位置指定 |
| S-06 | マイリスト | 訪問済み/行きたいの切り替え表示 |
| S-07 | プロフィール | 投稿一覧、フォロー/フォロワー数 |
| S-08 | 地図 | スポットをピンで表示、エリアタグ絞り込み |

## 7. データモデル(案)

| テーブル | 主な項目 |
|---|---|
| users | id, name, email, password_hash, created_at |
| refresh_tokens | id, user_id, token_hash, expires_at, revoked_at |
| spots | id, user_id, name, review, address, latitude, longitude, visibility(public / followers / private), created_at, updated_at |
| photos | id, spot_id, s3_key, sort_order |
| area_tags | id, name(47 都道府県のマスタ) |
| spot_tags | spot_id, tag_id(1 投稿 1〜3 個) |
| likes | user_id, spot_id, created_at(user_id+spot_id で一意) |
| comments | id, spot_id, user_id, body, created_at |
| follows | follower_id, followee_id, created_at(組で一意) |
| user_spots | user_id, spot_id, status(visited / wishlist), created_at(組で一意) |

## 8. 制約・前提条件

### 技術スタック

| 領域 | 採用 | 備考 |
|---|---|---|
| フロントエンド | Vue 3 + Nuxt | React / Vite / Material UI は使わない |
| UI | Tailwind CSS | Vuetify 等の Material 系は使わない |
| バックエンド | TypeScript + NestJS | Java / Spring Boot / Gradle は使わない。npm 管理 |
| DB | MySQL(RDS) | PostgreSQL は使わない |
| 画像保存 | Amazon S3 | |
| 地図 | Amazon Location Service + MapLibre GL JS | 地図表示と逆ジオコーディング。無料枠内で運用 |
| 実行基盤 | ECS Fargate + RDS | NAT Gateway は置かない |
| インフラ | AWS + Terraform | RaiseTimeLine を参考。リージョンは ap-northeast-1 を想定 |
| CI/CD | GitHub Actions | 次フェーズで整備 |

### 決定済み(v0.2)
- [x] 認証方式: JWT + リフレッシュトークン
- [x] 公開範囲: 公開 / フォロワー限定 / 非公開の 3 段階
- [x] エリアタグ: 47 都道府県の固定一覧(1 投稿 1〜3 個)
- [x] 「訪問済み/行きたい」: 自分の投稿は自動で訪問済み、他人の投稿は行きたいから開始
- [x] 写真: 1 枚 5MB 以下、1 投稿 20 枚まで、JPEG/PNG/WebP
- [x] UI: Tailwind CSS
- [x] 住所入力: 自由記述(最大 255 文字)+ 現在地からの自動入力
- [x] 実行基盤: ECS Fargate + RDS(MySQL)
- [x] 地図表示: 初版から実装する

### 決定済み(v0.3)
- [x] 地図サービス: Amazon Location Service(地図表示・逆ジオコーディング)。スタイル/タイルの選定は実装時に決める
- [x] 位置指定の操作: 地図タップでピンを置き、ドラッグで微調整
- [x] 地図の表示範囲取得 API: 表示範囲(南西・北東の緯度経度)を指定し、範囲内で閲覧権限のあるスポットを最大 100 件返す
- [x] 写真アップロード方式: 署名付き URL で S3 へ直接アップロード
- [x] 画像の縮小: アップロード前にブラウザ側で縮小(長辺 1600px 程度、仮)。サーバー側のサムネイル生成は行わない。一覧の代表画像は sort_order が先頭の写真

### 未決事項
- [ ] Amazon Location Service の無料枠・料金の確認と、利用上限(課金防止)の設定方法
- [ ] ブラウザ側縮小の具体値(長辺・画質)と、HEIC など非対応形式の扱い
