# TripDiary 要件定義書

Nov 14, 2026 · @masatsumaple-creator

## 1. 目的
旅行で訪れたスポットを、写真・感想・住所つきで記録し、他のユーザーと共有できる旅行記録アプリです。講座課題として、実際に AWS へデプロイして動作させるところまで作ります。

| 観点 | 内容 |
|---|---|
| 記録 | 訪れたスポットを場所名・感想・写真・住所で残せる |
| 共有 | 公開した投稿に、いいね・コメント・フォローで反応できる |
| 探索 | エリアタグで絞り込み、「訪問済み/行きたい」でリスト管理できる |

## 2. 想定ユーザー・利用シーン

| ユーザー | 利用シーン |
|---|---|
| 旅行好きの個人 | 旅行中・旅行後にスポットを記録し、思い出として見返す |
| 友人・フォロワー | 他の人のおすすめスポットを探し、行きたい場所に追加する |
| 閲覧のみの訪問者 | ログインせず公開投稿を閲覧する |

## 3. スコープ

| 作る | 作らない(初期版) |
|---|---|
| ユーザー登録・ログイン | SNS 連携ログイン |
| スポット投稿(場所名・感想・写真・住所) | 動画の投稿 |
| いいね、コメント、フォロー | ダイレクトメッセージ、通知(メール/プッシュ) |
| エリアタグ絞り込み | 地図表示、現在地検索 |
| 訪問済み/行きたいリスト | 旅行費用管理、旅程(行程表)作成 |

## 4. 機能要件

| 機能群 | 内容 |
|---|---|
| 認証 | 新規登録、ログイン、ログアウト、パスワードは保存時にハッシュ化 |
| スポット投稿 | 場所名(必須)、感想、写真(複数)、住所、エリアタグ、公開範囲の登録・編集・削除 |
| いいね | 投稿へのいいね/取り消し、件数表示 |
| コメント | 質問やおすすめ追加のコメント投稿、自分のコメントの削除 |
| フォロー | ユーザーのフォロー/解除、フォロー中ユーザーの投稿一覧 |
| 探索・絞り込み | エリアタグでの絞り込み、新着一覧 |
| スポットリスト | 他人の投稿を「行きたい」、自分の投稿や訪問後は「訪問済み」として管理 |
| プロフィール | ユーザーの投稿一覧、フォロー数・フォロワー数 |

### 権限マトリクス

| 操作 | 未ログイン | 本人 | 第三者(ログイン済み) |
|---|---|---|---|
| 公開投稿の閲覧 | ○ | ○ | ○ |
| 非公開投稿の閲覧 | × | ○ | × |
| 投稿の作成 | × | ○ | - |
| 投稿の編集・削除 | × | ○ | × |
| いいね・コメント・フォロー | × | (自分への操作は不可) | ○ |
| コメントの削除 | × | 自分のコメント、自分の投稿上のコメント | 自分のコメントのみ |
| リスト管理 | × | ○(自分のリストのみ) | - |

## 5. 非機能要件

| 観点 | 要件 |
|---|---|
| セキュリティ | 認証は JWT 等のトークン方式(詳細は未決)。パスワードはハッシュ化。SQL はプレースホルダで実行。秘密情報はコードに含めず環境変数/Secrets Manager で管理 |
| 権限 | API 側で本人・公開範囲を必ず検証する(画面制御だけに頼らない) |
| 入力検証 | サーバー側で必須・文字数・形式を検証。エラー応答の形式は統一 |
| 画像 | 形式は JPEG/PNG/WebP、1 枚あたり 5MB 以下、1 投稿あたり 5 枚まで(いずれも仮) |
| 性能 | 一覧は 20 件程度ずつのページング。課題規模のため厳密な SLA は設けない |
| API 仕様書 | OpenAPI(Swagger)を自動生成して公開 |
| UX | スマートフォン幅でも利用可能なレスポンシブ対応 |
| プライバシー | 非公開投稿は本人以外に API でも返さない。画像 URL の推測を困難にする |
| コスト | 大量課金を避ける。NAT Gateway 等の高額リソースは使わず、終了後は `terraform destroy` |

## 6. 画面構成

| ID | 画面 | 概要 |
|---|---|---|
| S-01 | ログイン/新規登録 | 認証 |
| S-02 | ホーム(新着一覧) | 公開投稿、エリアタグ絞り込み |
| S-03 | フォロー中一覧 | フォローしたユーザーの投稿 |
| S-04 | スポット詳細 | 写真、感想、住所、いいね、コメント、リスト追加 |
| S-05 | スポット投稿/編集 | 入力フォーム、写真アップロード |
| S-06 | マイリスト | 訪問済み/行きたいの切り替え表示 |
| S-07 | プロフィール | 投稿一覧、フォロー/フォロワー数 |

## 7. データモデル(案)

| テーブル | 主な項目 |
|---|---|
| users | id, name, email, password_hash, created_at |
| spots | id, user_id, name, review, address, visibility, created_at, updated_at |
| photos | id, spot_id, s3_key, sort_order |
| area_tags | id, name |
| spot_tags | spot_id, tag_id |
| likes | user_id, spot_id, created_at(user_id+spot_id で一意) |
| comments | id, spot_id, user_id, body, created_at |
| follows | follower_id, followee_id, created_at(組で一意) |
| user_spots | user_id, spot_id, status(visited / wishlist), created_at(組で一意) |

## 8. 制約・前提条件

### 技術スタック

| 領域 | 採用 | 備考 |
|---|---|---|
| フロントエンド | Vue 3 + Nuxt | React / Vite / Material UI は使わない。UI は Tailwind CSS 等を想定 |
| バックエンド | TypeScript + NestJS | Java / Spring Boot / Gradle は使わない。npm 管理 |
| DB | MySQL | PostgreSQL は使わない |
| 画像保存 | Amazon S3 | |
| インフラ | AWS + Terraform | RaiseTimeLine を参考。リージョンは ap-northeast-1 を想定 |
| CI/CD | GitHub Actions | 次フェーズで整備 |

### 未決事項
- [ ] 認証方式(JWT のみか、リフレッシュトークン併用か)
- [ ] 公開範囲の粒度(公開/非公開の 2 段階か、フォロワー限定を含めるか)
- [ ] エリアタグの定義(固定の一覧か、ユーザーの自由入力か)
- [ ] 「訪問済み/行きたい」の対象(他人の投稿のみか、自分の投稿も含むか)
- [ ] 写真の上限(枚数・サイズ)の確定
- [ ] 実行基盤(ECS Fargate か、より低コストな構成か)
- [ ] UI ライブラリ(Tailwind CSS 等)の確定
- [ ] 住所入力は自由記述か、郵便番号などの構造化入力か
