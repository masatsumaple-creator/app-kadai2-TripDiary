# TripDiary 設計書

Nov 14, 2026 · @masatsumaple-creator

要件は [00_要件定義書.md](00_要件定義書.md) を参照してください。本書はプロジェクト構成と技術方針を定めます。数値は仮です。

## 1. 全体方針

| 項目 | 方針 |
|---|---|
| リポジトリ | モノレポ(`frontend/`、`backend/`、`infra/`、`docs/`、`e2e/`) |
| Node.js | 24 LTS |
| 言語 | フロント・バックとも TypeScript(strict) |
| ローカル開発 | docker-compose で MySQL 8 を起動 |
| 静的解析 | ESLint + Prettier(フロント・バック共通の方針) |

### ディレクトリ構成(予定)
```
TripDiary/
├─ backend/    NestJS
├─ frontend/   Nuxt
├─ infra/      Terraform
├─ e2e/        Playwright
├─ docs/
├─ docker-compose.yml
└─ .github/workflows/
```

## 2. システム構成

| 要素 | 構成 |
|---|---|
| 配信 | CloudFront。静的ファイルは S3、`/api/*` は ALB(内部)経由で ECS Fargate へ転送 |
| API | ECS Fargate 上の NestJS |
| DB | RDS(MySQL) |
| 画像 | S3。署名付き URL でブラウザから直接アップロード |
| 地図 | Amazon Location Service |
| 秘密情報 | Secrets Manager |
| 課金対策 | NAT Gateway・インターフェイス型 VPC エンドポイントを置かない。使わないときは `terraform destroy` |

フロントと API は同一オリジンとし、CORS 設定は行いません。開発時は Nuxt のプロキシで `/api` を転送します。

## 3. バックエンド(NestJS)

| 項目 | 方針 |
|---|---|
| ORM | Prisma。スキーマとマイグレーションは Prisma Migrate で管理 |
| 構成 | 機能別モジュール(auth, users, spots, photos, likes, comments, follows, tags, lists, maps)。各モジュールは Controller / Service / DTO に分ける |
| バリデーション | class-validator + ValidationPipe |
| エラー応答 | `{ code, message, fieldErrors? }` に統一(ExceptionFilter で一元化) |
| 認証 | JWT(アクセストークン)+ リフレッシュトークン(HttpOnly Cookie、DB にはハッシュのみ、ローテーション) |
| 権限 | Guard で認証を、Service で公開範囲・本人確認を検証 |
| API 仕様 | @nestjs/swagger で OpenAPI を生成し、`docs/api/openapi.json` をコミット。仕様書と食い違う場合は仕様書を正とする |
| テスト | Jest + Supertest。DB を使うテストは Testcontainers(MySQL) |

## 4. フロントエンド(Nuxt)

| 項目 | 方針 |
|---|---|
| 描画方式 | SPA(`ssr: false`)の静的出力(`nuxt generate`) |
| 状態管理 | Pinia |
| スタイル | Tailwind CSS |
| 地図 | MapLibre GL JS + Amazon Location Service |
| 画像 | アップロード前にブラウザ側で縮小(長辺 1600px 程度) |
| テスト | Vitest + Vue Test Utils(単体)、Playwright(E2E、`e2e/`) |

## 5. CI/CD

| 項目 | 方針 |
|---|---|
| CI | GitHub Actions。PR と main への push で、lint、型チェック、単体・結合テスト、E2E を実行 |
| デプロイ | `workflow_dispatch` の手動実行。GitHub OIDC で AWS へ認証 |
| バックエンド | Docker build → ECR push(タグは git SHA)→ ECS サービス更新 |
| フロントエンド | `nuxt generate` → S3 sync → CloudFront invalidate |

## 6. 開発ルール

| 項目 | 方針 |
|---|---|
| ブランチ | `feature/*`、`docs/*`、`chore/*`、`test/*` から PR を出し、main へマージ。main へ直接 push しない |
| コミット | 件名は英語の命令形 |
| PR | マージはユーザーが実施 |
