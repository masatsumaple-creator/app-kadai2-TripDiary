# TripDiary 運用手順書(作る・確認する・消す)

Nov 20, 2026 · v0.4(提出用の環境の作成・確認を反映。CSP の本適用の注意を追加)

AWS の環境を、**何もない状態から作り、動作を確認し、消す**までの手順。使い捨ての運用(`docs/22_インフラ設計.md` の D4・10 章)。
構成と、各層の設計は `22_インフラ設計.md`、Terraform の細かい手順は [infra/README.md](../infra/README.md) を参照。

## 0. 前提(一度だけ)

- AWS CLI・Terraform・Docker・Node.js・GitHub CLI(`gh`)が使え、`aws sts get-caller-identity` と `gh auth status` が通る。
- Terraform の state 用 S3 バケット(`infra/bootstrap`)があり、`infra/backend.hcl` がある(どちらも、環境を消しても残す。`infra/README.md` の「初回」)。
- 費用: 動かしている間は、**約 $0.085/時**(約 ¥13/時。1 週間つけっぱなしで約 $14)。作って消すだけなら、1 回あたり数十円。**使わないときは、必ず消す**(「止める」では、ALB と RDS の課金が続く)。
- 予算のアラート: 月 $20 と $25 で、メールが届く(`infra/budgets.tf`。L1 で作成済みで、環境を消しても残る)。

## 1. 作る(約 20 分。そのうち、待ち時間が大半。リハーサルの実測: apply 13 分 30 秒、デプロイ 4 分 34 秒、デモデータ 12 秒)

| # | 作業 | コマンド・確認 | 所要の目安 |
|---|---|---|---|
| 1 | 最新の `main` にする。前の環境が残っていないことを確認 | `git checkout main && git pull` → `node scripts/cleanup-check.mjs`(「課金されるものは残っていません」) | |
| 2 | 計画を見る | `cd infra` → `export TF_VAR_budget_alert_email=<通知先のメールアドレス>` → `terraform init -reconfigure -backend-config=backend.hcl` → `terraform plan -out=tfplan`。**「Plan: 40 to add, 0 to change, 0 to destroy」**(L1 が残っている場合。写真・地図(Cognito)を含む)であること。想定外の変更・削除があれば、**apply しない** | 1 分 |
| 3 | 作る | `terraform apply tfplan`。待ち時間の大半は、RDS(約 10 分)と CloudFront の VPC オリジン(約 8 分)。並行して作られる | **約 13 分 30 秒** |
| 4 | GitHub の変数を更新 | リポジトリのルートで `node scripts/set-github-variables.mjs`(ロールの ARN・CloudFront のドメインなど。作り直すたびに変わる) | 数秒 |
| 5 | デプロイ | `gh workflow run deploy.yml --ref main` → `gh run watch`。イメージのビルド → マイグレーション → サービスの更新 → フロントの配置 → CloudFront の無効化 → 疎通確認まで、自動 | **約 4 分 30 秒** |
| 6 | デモデータを入れる | `node scripts/seed-demo-data.mjs https://<CloudFront のドメイン>`(ドメインは `terraform -chdir=infra output -raw cloudfront_domain_name`) | 数秒 |
| 7 | 動作を確認する | 下の「2. 動作確認」 | 5〜10 分 |

- **作成の順序は、守る必要がない**: ECS のサービスは、最初は、ECR にないイメージ(`bootstrap`)を取りに行って失敗し続けるが、#5 のデプロイが、最初のイメージを入れて直す(実機で確認済み)。
- #5 が失敗したら、`gh run view <ID> --log-failed` で原因を見る。直したら、そのまま、もう一度 `gh workflow run deploy.yml --ref main`(マイグレーションは、適用済みなら何もしない)。

## 2. 動作確認

ブラウザで `https://<CloudFront のドメイン>` を開く。

- [ ] 新着一覧に、デモ用の投稿 7 件(公開)が表示される。ナビに「地図」がある
- [ ] 「地図」で、実際の地図(日本)が表示され、デモ用の投稿(位置のあるもの)がピンで出る。ピンを押すと概要が出る。投稿フォームで、地図をタップしてピンを置け、「現在地から入力」で住所が入る(位置情報を許可する)
- [ ] 「投稿する」で、**写真を追加**して保存し、詳細に写真が出る。一覧のカードにも、代表の写真が出る(写真は、ブラウザから S3 へ直接アップロードされる)
- [ ] デモ用のアカウントでログインできる(`demo-haruka@example.com`、パスワードは `DemoPass123!`。他に `demo-kenta@example.com`、`demo-mika@example.com`)
- [ ] 投稿の作成・編集・削除、エリアの絞り込み、「もっと見る」
- [ ] 詳細で、いいね・コメント・マイリスト(行きたい / 訪問済み)・近くのスポット
- [ ] プロフィールで、フォロー・解除。「フォロー中」の一覧
- [ ] 公開範囲: ログアウトすると、フォロワー限定・非公開の投稿は見えない(直接の URL も、見つからない扱い)
- [ ] リロード・直接 URL(`/spots/1` など)で、画面が表示される(SPA のフォールバック)
- [ ] `https://<ドメイン>/api/health` が `{"status":"ok","db":"up"}`。`/api/docs`(Swagger UI)は、本番では無効(404)
- [ ] **CSP(ブラウザの読み込み制限)**: 主要な画面(新着、写真つきの詳細、地図、投稿フォームで写真を追加)で、ブラウザのコンソールに、`Content Security Policy` の違反が出ない。画面が壊れたときは、`terraform apply -var csp_enforce=false`(約 3 分)で、違反を報告するだけの Report-Only に戻して、原因を調べる
- [ ] **回数の制限**: 間違ったパスワードで、同じメールアドレスに 11 回ログインすると、11 回目から 429(「ログインの失敗が続いたため…」)になる(確認用には、ログインできないメールアドレスを使う。デモ用のアカウントでやると、15 分間ログインできなくなる)
- [ ] **DB の TLS**: デプロイが成功し、`/api/health` が `db: up`(RDS は TLS でない接続を拒否するため、これが動けば、TLS で接続できている)
- [ ] スクリーンショット・短い動画を記録する(提出物の代わりにもなる。作り直しに失敗した場合に備える)

コマンドでの簡易確認は、`gh run view` のデプロイの最後(疎通確認)と、`curl -s https://<ドメイン>/api/health`。

## 3. 確認の期間中(確認者の確認)

- 動かしたままにする。何もしなくてよい。
- 画面を更新したいとき(コードを直した場合): `main` にマージしてから、`gh workflow run deploy.yml --ref main`(入力で、バックエンド・マイグレーション・フロントを選べる)。
- 戻したいとき: 直前のタスク定義のリビジョンを指定して、`aws ecs update-service --cluster tripdiary --service tripdiary-backend --task-definition tripdiary-backend:<リビジョン>`。マイグレーションは、前に進めるだけ(元に戻さない)。
- 月の予算のメール($20 / $25)が届いたら、使用量を確認する。

## 4. 消す(約 11 分。リハーサルの実測: 10 分 45 秒)

**確認が終わったと、確認してから**行う(最終の環境は、消すと、データも消える)。

```bash
cd infra
export TF_VAR_budget_alert_email=<通知先のメールアドレス>
terraform plan -destroy -out=tfplan      # 消すものを確認する
```

- **L1(ネットワーク・ECR・予算のアラート)を残して、ほかを消す場合**(作り直しの前提。通常はこちら): `terraform state list` から、L1 のもの(`aws_vpc`・`aws_subnet`・`aws_internet_gateway`・`aws_route*`・`aws_vpc_endpoint`・`aws_security_group`・`aws_vpc_security_group_*`(`alb_from_cloudfront` を除く)・`aws_ecr_*`・`aws_budgets_*`)を除いて、`-target=` で指定する。**「Plan: 0 to add, 0 to change, N to destroy」の N と、一覧を確認してから** `terraform apply tfplan`。
- **すべて消す場合**(課題の最終。2026-11-22 に実施済み): ① `terraform destroy`(上の plan の結果を確認してから。L1・ECR・予算のアラートまで、すべて消える)② state のバケットは、中身(state の古い版・削除マーカーを含む)が残っていると、消せない。**① で、リソースがすべてなくなってから**、`node scripts/empty-tfstate-bucket.mjs tripdiary-tfstate-<アカウント ID>`(名前が `tripdiary-tfstate-` で始まるバケットだけが対象)で、中身を空にし、`cd infra/bootstrap && terraform destroy` でバケットを消す ③ GitHub の変数(`gh variable list`)も、消した環境を指しているため、削除する ④ `node scripts/cleanup-check.mjs`(ECR・state・VPC も「なし」になる)。ほかのプロジェクトのバケット(`raisetimeline-*` など)には、触らない。作り直すときは、`infra/README.md` の「初回」(state のバケットの作成)から行う。
- 消した後は、**必ず、片付けの確認**を行う:

```bash
node scripts/cleanup-check.mjs
```

課金されるもの(RDS、ECS、ALB、NAT、Elastic IP、CloudFront、シークレット、ログ、S3、IAM など)が残っていないことを、サービスごとに直接確認する(終了コード 0 なら、残りなし)。残っていたら、その名前が表示される。**タグでの検索は、索引の更新が遅れて、すでにないものが残って見えるため、使わない**。

## 5. つまずきやすい点

| 症状 | 原因・対処 |
|---|---|
| `terraform apply` が、CloudFront のレスポンスヘッダーポリシーで 400(`Content-Security-Policy that is a security header and cannot be set as custom header`) | CSP の本適用は、カスタムヘッダーではなく、`security_headers_config` の `content_security_policy` で指定する必要がある(`infra/cloudfront.tf` で対応済み)。apply が途中で失敗したときは、原因を直して、**もう一度 apply する**(作れたものは、そのまま。残りだけが作られる)。失敗している間に、デプロイを実行すると、デプロイ用ロールの権限が未作成で、ECR の認証が失敗する(apply の完了後に、再実行する) |
| ログインが、429(「ログインの失敗が続いたため…」)になる | 回数の制限(失敗が、メールアドレスごとに 10 回、IP ごとに 50 回)。15 分で、自動で解ける(`Retry-After` ヘッダーに、残りの秒数)。確認のために、わざと失敗させたときは、デモ用のアカウントではなく、使い捨てのメールアドレスを使う |
| デプロイで `Not authorized to perform sts:AssumeRoleWithWebIdentity` | OIDC のロールの信頼が合っていない。このリポジトリは、トークンの `sub` が ID の形式(不変のサブジェクト)。`github_oidc_subject_prefix`(`infra/variables.tf`)を確認する。`main` ブランチ以外から実行していないかも確認する |
| デプロイの「マイグレーション」で失敗 | ステップのログに、Prisma のエラーが出る。サービスは更新されない(前の版のまま) |
| `terraform apply` が長い | CloudFront の VPC オリジン(約 8 分)と RDS(約 10 分)。正常 |
| `/api/*` が 502・504 | ALB のターゲットが healthy でない(`aws elbv2 describe-target-health`)。タスクが起動できていない場合は、`aws ecs describe-services` のイベントと、`/ecs/tripdiary` のログを見る |
| Git Bash で、`aws logs tail /ecs/tripdiary` が失敗 | パスが書き換えられる。`MSYS_NO_PATHCONV=1` を付ける |
| デモデータを入れ直したい | 環境ごと作り直す(RDS のデータは、消すと消える)。同じ環境に追加するだけなら `--force` |
| 作成のたびに、URL が変わる | 標準のドメイン(`*.cloudfront.net`)を使うため。提出する URL は、提出日に作った環境のもの |
